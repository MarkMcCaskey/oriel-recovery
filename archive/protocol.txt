ORIEL-1 / FICTIONAL LINK AND TELECOMMAND ICD / 1.3

This protocol exists only inside the simulator. No radio device interface,
frequency, callsign, authentication credential or operational network exists.

LINK FRAME
 a7 5c | sequence:u16_le | payload_length:u16_le | payload | crc:u16_le
CRC-16/CCITT-FALSE: polynomial 1021, initial ffff, no reflection, xorout 0.
CRC covers the sync bytes, sequence, length and payload. Test vector
'123456789' -> 29b1. Payload limit 257 bytes. Sequence counters wrap at 65536.
Direction counters are independent. Duplicates are NOT automatically removed.

Every frame costs its byte length plus 16 bytes of preamble/turnaround,
with ten coded channel bits per byte. Duration in milliseconds is rounded
up. Uplink is 1200 bit/s (optional 300); downlink is 2400. Separate simulated
channels permit simultaneous up/down traffic. Command execution and response
transmission add latency; uplink delivery alone does not indicate success.
RF errors are deterministic from saved PRNG state, more frequent close to
the horizon. Failed uplinks are discarded. Corrupted downlinks fail CRC.
A frame must fit entirely within visibility to be received. No partial
frame executes. Multiple complete chunks can survive an interrupted upload.

TELECOMMAND PAYLOAD (all multibyte arguments little-endian)
01                          ECHO / identity
02 ADDRESS:u16 LENGTH:u16   Read up to 128 bytes from memory below c000.
03 ADDRESS:u16 DATA...       Load 1..128 bytes to 8800..8fff workspace.
05 SERVICE:u16              Invoke an engineering service.
06                          Request OBC reset.
07                          Update: begin.
08 DATA...                  Update: transfer block.
09                          Update: commit.

SERVICE DIRECTORY (operations-approved identifiers)
0 Identity/echo; 1 engineering record; 2 instrument sample; 3 build identity.
Call completion may be silent. The ICD defines only these four services.
Use only behavior confirmed for the actual linked flight build; archival
source versions are identified in manifest.txt.

RESPONSE TYPES (first payload byte)
80 LINK BEACON    uptime_seconds:u32, supervisor_reset_count:u32.
                 Generated independently of application code every 60 s.
81 ECHO           Identity bytes from software.
82 MEMORY         Requested bytes; correlating requests is the operator's job.
83 ACK            For workspace loads: command byte + address:u16.
e0 FLIGHT STATUS  Two bytes: operation, result. Result 01 malformed/unknown;
                 result 02 unavailable in this software configuration.
90 ENGINEERING    Forty-byte recorder record; see telemetry.txt.

UPDATER STATUS
The update command numbers were allocated before launch. A specification
is not a flight acceptance record. See update-notes.txt for project history.

GROUND TOOLS
'send' encodes common payloads. 'send hex' accepts arbitrary payload bytes.
'frame' calculates framing locally; 'raw' queues your exact complete frame.
No local tool can bypass packet duration, CRC, flight software dispatch,
workspace permissions, device timing, or line-of-sight constraints.
